## Point-by-point answers

1. **Threading:** partials run on `Dispatchers.Default` (consumer coroutine, SB1-04 solved for partials); **the finale runs via `runBlocking` on the main thread** (C-1). The scope is cancelled in `onDestroy` via `serviceScope.cancel()` ✓.
2. **While-in-use/FGS:** order grant→`startForegroundService`→`Coordinator.start()` observed (lines 135-140); `CaptureForegroundService` calls `startForeground` immediately in `onStartCommand`. `onWindowHidden`/`onFinishInputView`/`onDestroy` → `stopDictationIfRunning()` + `stopFgs()` ✓. Gap: a `start()` throw leaves the FGS behind (C-5).
3. **Push-to-talk:** down/up/cancel symmetric, duplicate down via the `state==RECORDING` guard, `ACTION_CANCEL`→stop, `performClick()` on down; **no try/finally around `start`** (C-5). Short press (<200 ms) → start+stop with drain, ok.
4. **Permission fallback:** `permanentlyDenied` empty ⇒ endless re-asking, `PermanentlyDenied` dead (C-3). The tests check the pure logic correctly but not the wiring (C-7).
5. **Error path without a model:** engine never `.load()` ⇒ the first `transcribe` throws ⇒ `fail(asr_partial_error)` ⇒ **invisible** (status "Bereit") and **microphone stays open** (C-2). No crash (the error is caught in `feedAudio`), but silent.
6. **Route display:** actual route (`currentRoute`), not preference ✓; loss visible, but the recording is not terminated (C-6).
7. **Resources:** `AudioRecord` release in `stop()`/`abort()` ✓; **`OrtSession`/engine never closed** (C-4); `Handler`/`BroadcastReceiver`: `AudioRouter` observing is stopped in `onDestroy` ✓.
8. **Privacy:** no text/audio logs (only durations/codes/permission names); merged manifest without `INTERNET`/`TelemetryInitializer` ✓.
9. **Test quality:** 7 DictationPermissions tests real, but without a wiring and lifecycle test (C-7).

---

## Verdict

**Release only with fixes.** Three P1s (C-1 main-thread finale, C-2 invisible ASR error + open microphone, C-3 endless re-asking on permanent denial). The core (threading of the partials, FGS ordering, push-to-talk semantics, privacy) is solid; the three P1s are integration/robustness defects that must be fixed before release.

## Top-5 actions

1. **C-1** — Move the final decode into the `serviceScope` (no `runBlocking` on main); `stop()` suspend/completion-based.
2. **C-2** — Mirror `controller.lastErrorCode` (or the `fail` signal) into `coordinator.lastError`/UI **and** stop the capture on a controller failure (`abort()`); additionally wire `engine.load(modelDir)`.
3. **C-3** — Feed `permanentlyDenied` from `AndroidPermissionsRequester.permanentlyDeniedSet()` and persist it on the way back → settings path instead of an endless dialog.
4. **C-4** — `engine.load()` **and** `engine.close()` in the service lifecycle layer (no 0.9-GB OrtSession leak once the model loads).
5. **C-5/C-6** — Put `coordinator.start()` in try/finally (stop the FGS on error); cleanly terminate route loss during `RECORDING`; add one lifecycle test each ("RECORDING + onFinishInputView ⇒ IDLE", "start throws ⇒ FGS stopped").
